Reference

How it works, anti-spam, settings & troubleshooting

The full mechanics behind every call Ringback places — the notification pipeline, the anti-spam gates, every config field, and what to check when a call doesn't happen.

How it works

One notification, six steps, one phone call — or none

Every call starts as a Notification hook and passes through the same pipeline before it's ever placed.

ring 1

Notification fires

Claude Code emits permission_prompt, idle_prompt, or agent_needs_input.

t+0s
ring 2

schedule-call.mjs checks in

Skips if the event isn't in your configured events list, or if a call is already pending for this session.

t+0s
ring 3

Pending file written, clock starts

Writes pending/<session_id>.json and sleeps for delay_seconds.

t+0s
ring 4

Wakes up, checks again

If the pending file is gone, you already came back — exit quietly. If it's still there, the anti-spam guard runs a second time.

t+180s
ring 5

The call goes out

provider.placeCall() — Twilio or your webhook — dials your configured phone_number.

t+180s
ring 6

Logged and cleared

Result appended to call-ledger.jsonl, pending file deleted either way.

t+180s
Any real activity cancels it. Submitting a prompt, the turn ending, or the session closing all delete the pending file before the timer runs out — UserPromptSubmit, Stop, and SessionEnd each call cancel-call.mjs. One exception: Stop leaves a pending idle_prompt call in place, since a turn can end at the exact moment an idle call gets scheduled for it — only genuine activity (a new prompt, or the session ending) cancels that one.

Anti-spam model

Never silent, never spammy

Every call passes four gates, in order, checked once when it's scheduled and again right before it dials.

180s
Delay before calling

A prompt has to sit unanswered this long before Ringback pays attention. Most prompts get answered well before that.

30min
Cooldown

The same session won't call you again sooner than this, even if it keeps sitting blocked.

5/day
Daily cap

An upper bound across every session you run, so a bad afternoon can't turn into a dozen calls.

off
Quiet hours

Optional window, e.g. 23:00-07:00, where no calls go out at all.

Troubleshooting

Read the log first

Ringback writes every decision to ${CLAUDE_PLUGIN_DATA}/ringback.log — it rotates to .log.1 once it passes 1 MB.

schedule: skip ... (not in configured events)The notification type isn't in your events list, or a call is already pending for this session.
schedule: aborted ... reason=quiet_hours|cooldown|daily_capThe anti-spam guard blocked it — check your gate settings.
schedule: call FAILED ...The provider rejected the call — the error message from Twilio or your webhook follows.
cancel: cancelled session=... trigger=...You came back in time. Nothing else to do.
On Unix-like systems, scripts/schedule-call.mjs and scripts/cancel-call.mjs need their executable bit set: chmod +x scripts/schedule-call.mjs scripts/cancel-call.mjs.
Extension point

Adding a first-class voice provider takes three changes: a file in scripts/lib/providers/ exporting async placeCall(payload, config), one line in the provider registry, and any new userConfig keys in plugin.json (mark credentials sensitive: true).

Non-goals for v0.1
  • No two-way voice response — the call is one-way, and directs you to the Claude app to respond.
  • No SMS/WhatsApp fallback.
  • No bundled MCP server, skill, or agent — hooks and scripts only.
