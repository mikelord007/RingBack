A blocked session is silent. You only find out when you happen to check back.

Claude Code sessions can sit waiting on a permission prompt, or idle for your next message, for a long time once you've stepped away from the terminal. Ringback closes that gap with a phone call — through Twilio or any webhook-compatible voice provider you already run.

How it works

One notification, six steps, one phone call — or none

Every call starts as a Notification hook and passes through the same pipeline before it's ever placed.

ring 1

Notification fires

Claude Code emits permission_prompt, idle_prompt, or agent_needs_input.

t+0s
ring 2

schedule-call.mjs checks in

Skips if the event isn't in your configured events list, or if a call is already pending for this session.

t+0s
ring 3

Pending file written, clock starts

Writes pending/<session_id>.json and sleeps for delay_seconds.

t+0s
ring 4

Wakes up, checks again

If the pending file is gone, you already came back — exit quietly. If it's still there, the anti-spam guard runs a second time.

t+180s
ring 5

The call goes out

provider.placeCall() — Twilio or your webhook — dials your configured phone_number.

t+180s
ring 6

Logged and cleared

Result appended to call-ledger.jsonl, pending file deleted either way.

t+180s
Any real activity cancels it. Submitting a prompt, the turn ending, or the session closing all delete the pending file before the timer runs out — UserPromptSubmit, Stop, and SessionEnd each call cancel-call.mjs. One exception: Stop leaves a pending idle_prompt call in place, since a turn can end at the exact moment an idle call gets scheduled for it — only genuine activity (a new prompt, or the session ending) cancels that one.

Anti-spam model

Never silent, never spammy

Every call passes four gates, in order, checked once when it's scheduled and again right before it dials.

180s
Delay before calling

A prompt has to sit unanswered this long before Ringback pays attention. Most prompts get answered well before that.

30min
Cooldown

The same session won't call you again sooner than this, even if it keeps sitting blocked.

5/day
Daily cap

An upper bound across every session you run, so a bad afternoon can't turn into a dozen calls.

off
Quiet hours

Optional window, e.g. 23:00-07:00, where no calls go out at all.

Pick a line

Twilio, or bring your own voice provider

Ringback ships with two ways to actually place the call.

Twilio
  • Set provider to twilio
  • Needs Account SID, Auth Token, and a Twilio-owned from number
  • Trial accounts can only call verified numbers — verify your own phone_number in the Twilio console first
  • Trial accounts also play Twilio's own upgrade disclaimer before Ringback's message — that's Twilio, not Ringback
Webhook
  • Set provider to webhook and a webhook_url
  • Wire in Vapi, Bland, Telnyx, a self-hosted service, an n8n workflow — anything that accepts a POST
  • 10 second timeout; non-2xx responses count as a failed call
  • Zero code changes to the plugin itself

Set up with Claude Code

From zero to your first call

Everything below runs inside Claude Code — no separate dashboard, no manual config files.

Add the marketplace and install

Run both commands in a Claude Code session:

claude plugin marketplace add mikelord007/RingBack
claude plugin install ringback@ringback-marketplace
Installing doesn't configure the plugin by itself — you still need the next step.

Open /plugins and configure it

Run /plugins inside Claude Code, select ringback, and open its configuration screen. That walks you through every field in the settings table above — phone_number and provider are the two that matter first. Everything else has a sane default.

If you're using Twilio

Sign up at twilio.com and claim a free trial number. On the Console dashboard, copy your Account SID and Auth Token into twilio_account_sid / twilio_auth_token, and put the trial number itself into twilio_from_number.

Trial accounts can only call numbers you've verified — verify your own phone_number first under Verified Caller IDs, or calls to it will fail.

Regional note: outbound voice calling is subject to carrier and regulatory constraints by country. In India specifically, DLT/TRAI registration can block or restrict calls to Indian numbers through generic voice providers — confirm your provider actually supports your number's country, or use the webhook provider to route through a local, compliant one instead.

If you're using your own voice provider

Set provider to webhook and point webhook_url at any endpoint you control. It'll receive the JSON payload shown above with header X-Ringback-Event: call — see the providers section for the full contract.

Confirm it's wired up

Run claude --debug and check that Notification, UserPromptSubmit, Stop, and SessionEnd from hooks/hooks.json show up as registered. Then watch ${CLAUDE_PLUGIN_DATA}/ringback.log the next time a session goes idle.

Edited hooks/hooks.json yourself, or updated the plugin? Hook wiring loads once per session — run /reload-plugins, or restart the CLI, for changes to take effect.

Troubleshooting

Read the log first

Ringback writes every decision to ${CLAUDE_PLUGIN_DATA}/ringback.log — it rotates to .log.1 once it passes 1 MB.

schedule: skip ... (not in configured events)The notification type isn't in your events list, or a call is already pending for this session.
schedule: aborted ... reason=quiet_hours|cooldown|daily_capThe anti-spam guard blocked it — check your gate settings.
schedule: call FAILED ...The provider rejected the call — the error message from Twilio or your webhook follows.
cancel: cancelled session=... trigger=...You came back in time. Nothing else to do.
On Unix-like systems, scripts/schedule-call.mjs and scripts/cancel-call.mjs need their executable bit set: chmod +x scripts/schedule-call.mjs scripts/cancel-call.mjs.

Privacy & security

What leaves your machine

The only outbound calls this plugin makes are to the provider you configure — Twilio, or your own webhook_url. There's no telemetry.

●Credentials (twilio_account_sid, twilio_auth_token, webhook_url) are stored via Claude Code's OS keychain, never written to disk in plaintext.
●ringback.log never writes provider credentials.
●Provider error bodies are truncated to 500 characters before landing in any log or error message.
●The notification message is capped at 300 characters, both when the call is scheduled and again by the provider before it's sent.
●The call ledger only keeps the last 7 days of entries — older ones are pruned automatically.
●Stale pending files older than 24 hours are cleaned up on session end.
Extension point

Adding a first-class voice provider takes three changes: a file in scripts/lib/providers/ exporting async placeCall(payload, config), one line in the provider registry, and any new userConfig keys in plugin.json (mark credentials sensitive: true).

Non-goals for v0.1
  • No two-way voice response — the call is one-way, and directs you to the Claude app to respond.
  • No SMS/WhatsApp fallback.
  • No bundled MCP server, skill, or agent — hooks and scripts only.
